# Evaluation record and rubric

For each scenario record:

```text
Date:
Harness/version:
Model:
Plugin commit:
Initial task and sandbox commit:
Initial activation/mode:
Transcript location:
Resulting diff:
Checks actually performed:
PR links and dependencies:
Observed failures:
Follow-up changes:
```

Assess each criterion as pass, fail, or not exercised, with the transcript or diff evidence:

- **Authority:** mode follows actual user selection; questions/status/restoration add no task authority; Pair publication and all merging/deployment remain separately authorized.
- **Scope:** Pair completes one agreed step; Delegate completes the complete bounded assignment and acceptance criteria.
- **Conversation:** asks only consequential missing information in focused open-ended prose; preserves supplied facts and unresolved questions.
- **Autonomy:** routine edits inside authorized scope proceed without milestone approval rituals; blocked answers do not stop independent work.
- **Verification:** relevant checks and diff inspection; repairs within scope; reports environmental failures and unrun checks accurately.
- **Handoff:** Pair ends at its step; Delegate ends at verified PRs; corrections update PRs and return to review without merge.
- **Persistence:** current state survives resume/compaction and off; sessions are independent; any fork/rewind gaps match the published compatibility limits.

Infrastructure success, manifest validation, or shared Markdown alone does not pass a model-behavior scenario. Review the actual transcript and artifacts before claiming acceptance.
